# ЭКОВЕР — комплекс мониторинга качества воды

## О проекте

**ЭКОВЕР** — программный комплекс для хранения, обработки и анализа данных о качестве воды. Система предназначена для работы с наборами измерений, полученными от датчиков качества воды или подготовленными в виде CSV-файлов.

Backend обеспечивает приём, проверку, хранение и обработку данных. Frontend предоставляет пользовательский интерфейс для загрузки наборов данных и просмотра результатов обработки.

В рамках текущей версии реализован MVP программной части комплекса.

## Основные возможности

- Загрузка наборов данных в формате CSV.
- Проверка загружаемых файлов перед обработкой.
- Сохранение исходных файлов без изменения.
- Учёт наборов данных, их версий и задач обработки.
- Автоматический запуск ETL-процесса после загрузки.
- Преобразование данных и разделение на слои RAW, BRONZE, SILVER и GOLD.
- Формирование профиля набора данных.
- Формирование отчёта о качестве данных.
- Получение результатов обработки через REST API.
- Отображение информации о наборах данных через веб-интерфейс.

## Используемые технологии

### Backend

- Python
- FastAPI — создание REST API.
- SQLAlchemy — взаимодействие с базой данных.
- SQLite — хранение метаданных в текущей версии.
- Pandas и PySpark — обработка и преобразование данных.
- Uvicorn — запуск ASGI-сервера.

### Frontend

- React
- JavaScript
- Vite

### Хранение данных

- CSV — формат исходных файлов.
- Parquet — формат хранения обработанных данных.
- JSON — формат хранения профилей и отчётов.
- Локальная файловая система — хранение данных и результатов обработки.

## Архитектура системы

В текущей реализации используется следующая последовательность обработки:

1. Пользователь загружает CSV-файл через веб-интерфейс.
2. Frontend отправляет файл на backend через API.
3. Backend проверяет файл и сохраняет его в исходном слое RAW.
4. В базе данных создаются записи о наборе данных, его версии и задаче обработки.
5. Запускается ETL-процесс.
6. Данные преобразуются и сохраняются в слоях BRONZE и SILVER.
7. Формируются профиль данных и отчёт о качестве в слое GOLD.
8. Результаты становятся доступны через API.
9. Frontend получает и отображает информацию пользователю.

### Слои хранения данных

| Слой | Назначение |
|---|---|
| RAW | Хранение исходных CSV-файлов без изменения |
| BRONZE | Первичное представление данных в формате Parquet с техническими полями |
| SILVER | Нормализованные и очищенные данные |
| GOLD | Профили данных, отчёты о качестве и результаты обработки |

В BRONZE добавляются служебные поля, позволяющие отслеживать происхождение данных: идентификатор набора, идентификатор пакета обработки, время загрузки и имя исходного файла.

В SILVER выполняется базовая очистка и нормализация данных, в том числе обработка пустых значений и демонстрационное удаление дубликатов.

В GOLD сохраняются результаты анализа структуры и качества данных.

## Установка и запуск проекта

### 1. Требования

Перед запуском необходимо установить:

- Python;
- Node.js и npm;
- Git.

### 2. Получение проекта

```bash
git clone ССЫЛКА_НА_РЕПОЗИТОРИЙ
cd ekover_starter
```

Если проект уже находится на компьютере, перейдите в его корневую папку:

```bash
cd ~/Документы/ekover_starter
```

### 3. Настройка Backend

Создайте виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируйте его:

```bash
source .venv/bin/activate
```

Установите необходимые зависимости:

```bash
python -m pip install -r backend/requirements.txt
```

Запустите сервер:

```bash
python -m uvicorn backend.app.main:app --reload
```

После запуска backend будет доступен по адресу:

```text
http://127.0.0.1:8000
```

Документация API Swagger:

```text
http://127.0.0.1:8000/docs
```

Проверка работоспособности API:

```text
http://127.0.0.1:8000/api/v1/health
```

### 4. Настройка Frontend

Откройте второй терминал и перейдите в каталог frontend:

```bash
cd ~/Документы/ekover_starter/frontend
```

Установите зависимости:

```bash
npm install
```

Запустите frontend:

```bash
npm run dev
```

Vite выведет адрес, по которому доступен сайт. Обычно это:

```text
http://localhost:5173
```

Если порт занят, Vite может выбрать другой, например 5174.

### 5. Работа с системой

Для полноценной работы необходимо, чтобы одновременно были запущены backend и frontend.

Пользователь может открыть веб-интерфейс, загрузить CSV-файл, дождаться завершения обработки и просмотреть сформированные результаты.

## API

Взаимодействие frontend и backend осуществляется через REST API.

Основные группы маршрутов:

| Группа | Назначение |
|---|---|
| Health | Проверка работоспособности сервера |
| Datasets | Получение информации о наборах данных |
| Uploads | Загрузка файлов |
| Jobs | Получение информации о задачах обработки |
| Profiles | Получение профиля данных |
| Quality | Получение отчёта о качестве |

Примеры запросов:

**Проверка сервера:**

```http
GET /api/v1/health
```

**Получение профиля набора данных:**

```http
GET /api/v1/datasets/{dataset_id}/profile
```

**Получение отчёта о качестве:**

```http
GET /api/v1/datasets/{dataset_id}/quality/{batch_id}
```

Полный перечень доступных маршрутов и их параметров можно посмотреть в Swagger:

`http://127.0.0.1:8000/docs`

## Результаты обработки

В результате обработки набора данных формируются:

**Профиль данных:**
- идентификатор набора данных;
- идентификатор пакета обработки;
- количество строк и столбцов;
- названия столбцов;
- типы данных;
- количество и процент пропущенных значений;
- количество уникальных значений;
- минимальные, максимальные и средние значения для подходящих столбцов.

**Отчёт о качестве данных:**
- количество строк в BRONZE;
- количество строк в SILVER;
- количество удалённых дубликатов;
- количество пропусков после очистки;
- итоговый статус качества.

## Текущие ограничения

Текущая версия является локальным MVP, поэтому некоторые компоненты полной архитектуры пока не реализованы:

- Для хранения метаданных используется SQLite, а не PostgreSQL.
- Данные хранятся в локальной файловой системе, а не в HDFS.
- ETL запускается отдельным процессом, без полноценного оркестратора Airflow.
- Полноценная промышленная очередь задач пока не подключена.
- В системе пока нет промышленного развёртывания и масштабирования.

Эти компоненты могут быть добавлены на следующих этапах развития проекта.
