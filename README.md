# ЭКОВЕР — комплекс мониторинга и анализа качества воды

## О проекте

**ЭКОВЕР** — программный комплекс для загрузки, хранения, обработки и анализа данных о качестве воды. Система предназначена для работы с наборами измерений, полученными от датчиков качества воды или подготовленными в формате CSV.

Проект разрабатывается как модульная платформа, объединяющая:
- приём и проверку исходных данных;
- ETL-обработку;
- многоуровневое хранение данных;
- контроль качества и профилирование;
- аналитический пользовательский интерфейс;
- интеграцию алгоритмов машинного обучения;
- обнаружение аномалий;
- оркестрацию процессов обработки.

Текущая версия представляет собой MVP программной платформы комплекса «ЭКОВЕР».

## Основные возможности

### Работа с данными
- Загрузка CSV-файлов через веб-интерфейс.
- Проверка формата, структуры и размера загружаемых файлов.
- Сохранение исходных файлов.
- Учёт наборов данных, версий и задач обработки.
- Получение информации о состоянии обработки.

### ETL и хранилище
- Преобразование данных с использованием ETL-процессов.
- Организация слоёв RAW, BRONZE, SILVER и GOLD.
- Хранение обработанных данных в формате Parquet.
- Формирование профилей наборов данных.
- Формирование отчётов о качестве данных.
- Сохранение результатов выполнения ETL.

### Аналитика
- Просмотр количества строк и столбцов.
- Анализ типов данных.
- Определение количества и процента пропусков.
- Расчёт количества уникальных значений.
- Просмотр минимальных, максимальных и средних значений.
- Просмотр отчётов качества данных.

### Машинное обучение
- Получение списка зарегистрированных моделей.
- Интеграция с процессами обучения моделей.
- Запуск инференса.
- Получение результатов предсказаний.
- Просмотр обнаруженных аномалий.
- Просмотр истории запусков ML-процессов.

Алгоритмы машинного обучения развиваются как отдельный модуль и интегрируются с основной платформой через backend API.

## Архитектура проекта

Система состоит из нескольких основных компонентов:

| Компонент | Назначение |
|---|---|
| React Frontend | Пользовательский интерфейс |
| FastAPI Backend | REST API и бизнес-логика |
| PostgreSQL | Хранение метаданных |
| ETL | Проверка, преобразование и подготовка данных |
| Data Lake | Хранение исходных и обработанных наборов |
| Apache Airflow | Оркестрация процессов обработки |
| ML-модуль | Обучение моделей, инференс и обнаружение аномалий |
| Docker Compose | Запуск и взаимодействие сервисов |

### Общая последовательность обработки

1. Пользователь загружает CSV-файл через веб-интерфейс.
2. Frontend отправляет файл в FastAPI.
3. Backend проверяет файл и сохраняет исходные данные в RAW.
4. В PostgreSQL сохраняются метаданные набора данных, версии и задач обработки.
5. Запускается ETL-процесс.
6. Данные преобразуются и сохраняются в слоях BRONZE и SILVER.
7. В GOLD формируются аналитические витрины и отчёты.
8. Backend предоставляет результаты через REST API.
9. Frontend отображает результаты обработки и аналитики.
10. ML-модуль использует подготовленные данные для обучения и инференса.

### Слои хранения данных

| Слой | Назначение |
|---|---|
| RAW | Исходные файлы без изменения |
| BRONZE | Первичное представление данных в Parquet с техническими полями |
| SILVER | Очищенные и нормализованные данные |
| GOLD | Аналитические витрины, профили и отчёты качества |

В BRONZE сохраняются технические сведения, необходимые для отслеживания происхождения данных: идентификаторы набора и пакета обработки, время загрузки и информация об исходном файле.

В SILVER выполняются базовая очистка и нормализация, обработка пропущенных значений и демонстрационные преобразования.

В GOLD формируются результаты профилирования, контроля качества и аналитические данные.

## Установка и запуск

### 1. Требования

Для работы с проектом необходимы:

- Git;
- Docker;
- Docker Compose;
- доступ к локальным портам 5173, 8000 и 8080.

Для локальной разработки без Docker дополнительно потребуются Python, Node.js и npm.

### 2. Получение проекта

```bash
git clone https://github.com/musipuska/ekover2.git
cd ekover2
```

### 3. Настройка переменных окружения

Проверь наличие файла `.env.example`.

Если он предусмотрен проектом, создай локальный `.env` на его основе:

```bash
cp .env.example .env
```

Заполни необходимые параметры подключения к PostgreSQL и другие переменные, предусмотренные конфигурацией проекта.

Не публикуй `.env`, пароли, токены и секретные ключи в GitHub.

### 4. Запуск через Docker Compose

Из корневого каталога проекта выполни:

```bash
sudo docker compose build
```

Затем запусти сервисы:

```bash
sudo docker compose up -d
```

Проверь состояние контейнеров:

```bash
sudo docker compose ps
```

Для просмотра логов:

```bash
sudo docker compose logs --tail=100
```

Для просмотра логов конкретного сервиса:

```bash
sudo docker compose logs --tail=100 api
sudo docker compose logs --tail=100 frontend
sudo docker compose logs --tail=100 airflow
```

### 5. Доступ к сервисам

После успешного запуска:

| Сервис | Адрес |
|---|---|
| Frontend | http://localhost:5173 |
| Backend API | http://localhost:8000 |
| Swagger | http://localhost:8000/docs |
| Airflow | http://localhost:8080 |

Доступность отдельных страниц и API зависит от успешного запуска соответствующих сервисов и настройки окружения.

### 6. Остановка проекта

Для остановки контейнеров без удаления данных:

```bash
sudo docker compose stop
```

Для повторного запуска:

```bash
sudo docker compose start
```

Не используй `docker compose down -v` без необходимости: эта команда может удалить тома с данными PostgreSQL.

## REST API

Взаимодействие между frontend и backend выполняется через REST API.

Основные группы маршрутов:

| Группа | Назначение |
|---|---|
| Health | Проверка состояния backend |
| Datasets | Получение информации о наборах данных |
| Uploads | Загрузка CSV-файлов |
| Jobs | Получение состояния задач обработки |
| Profiles | Получение профиля данных |
| Quality | Получение отчётов качества |
| ML Models | Получение информации о моделях |
| ML Training | Запуск обучения |
| ML Inference | Запуск инференса |
| ML Runs | Получение истории запусков |
| Predictions | Получение результатов предсказаний |
| Anomalies | Получение обнаруженных аномалий |

Примеры запросов:

**Получение списка наборов данных:**

```http
GET /api/v1/datasets
```

**Получение профиля набора данных:**

```http
GET /api/v1/datasets/{dataset_id}/profile
```

**Получение отчёта качества:**

```http
GET /api/v1/datasets/{dataset_id}/quality/{batch_id}
```

**Получение истории ML-запусков:**

```http
GET /api/v1/ml/runs
```

Полный перечень маршрутов, параметров и моделей ответов доступен в Swagger:

http://localhost:8000/docs

## Результаты обработки данных

### Профиль данных

Профиль набора данных содержит:

- идентификатор набора данных;
- идентификатор пакета обработки;
- количество строк и столбцов;
- названия столбцов;
- типы данных;
- количество пропущенных значений;
- процент пропусков;
- количество уникальных значений;
- минимальные и максимальные значения;
- средние значения для подходящих столбцов.

### Отчёт о качестве

Отчёт качества может содержать:

- количество строк в BRONZE;
- количество строк в SILVER;
- количество удалённых дубликатов;
- количество пропусков после очистки;
- итоговый статус качества.

### ML-результаты

ML-модуль предусматривает получение:

- сведений о зарегистрированных моделях;
- информации о запусках обучения;
- результатов инференса;
- оценок аномальности;
- признаков обнаруженных аномалий;
- истории выполнения ML-задач.

Фактический состав результатов зависит от подключённой модели и версии ML-модуля.
